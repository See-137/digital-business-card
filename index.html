01 / 04

CMA: Cost Monitoring Agent

Open source

LLM cost monitoring and attribution, with a RAG assistant that explains why the bill moved.

Problem
A provider's billing page shows a total. It does not say which agent spent it, on which model, or why spend changed.
Approach
A Python SDK patches OpenAI, Anthropic and LangChain clients in place and records tokens and cost at the call site. A FastAPI service attributes spend per agent, model and provider, checks budgets set globally or per agent and workflow, and alerts by webhook, Slack or in the app as a budget fills. Scrooge, the built-in RAG assistant, embeds cost events and rollups into a vector store and explains spend changes with cited sources.
Trade-off
SQL is the source of truth and the vector store is only a cache, so a corrupted index can be rebuilt and never loses data. Scrooge answers “how much” from SQL and uses retrieval only for “why”. Retrieval quality is not scored yet: a golden-question set is still on the roadmap.
Evidence
The source is public under the MIT licence and runs on your own infrastructure with Docker Compose. A failure in the SDK never breaks the LLM call it wraps. CI checks that every database migration is reversible against a real PostgreSQL.

02 / 04

FinPulse

Live demo

A portfolio tracker, and the serverless AWS platform and delivery pipelines that run it.

Problem
The dashboard is the visible part. Behind it, one engineer has to run sign-in, market data, an AI copilot and payments reliably, and ship changes safely.
Approach
Terraform defines the platform: Lambda functions behind API Gateway with a Cognito authoriser and throttling, DynamoDB on demand, secrets in Secrets Manager, and the React front end on S3 behind CloudFront. Separate GitHub Actions pipelines cover checks, security scans, infrastructure and deploys. An AI copilot answers questions about your positions from its own function.
Trade-off
One region and one environment: staging was retired. Deploys run without a manual approval, so the safety net is green CI, a smoke test after each deploy and a revert.
Evidence
The site is public at finpulse.me. CloudWatch alarms watch Lambda errors and API errors and latency. DynamoDB has point-in-time recovery. Market data falls back from memory to a cache table, then the live API, then a static copy. Infrastructure changes apply only from a saved Terraform plan.

03 / 04

Editorial Automation Platform

Client work, unbranded

Scheduled news ingestion, structured LLM translation with quality checks, and an editor's approval before anything is published.

Problem
A Hebrew magazine wants English-language news translated quickly. Names, terms and right-to-left layout have to survive, and nothing may go out unreviewed.
Approach
A cron trigger pulls allow-listed feeds on a schedule, and each new article becomes one queue message with retries and a dead-letter queue. A worker extracts clean text, then makes one model call that must return JSON matching a schema. Fixed glossary terms are masked before the call and restored after it. Every article waits in a review queue behind Cloudflare Access, where an editor approves, rejects, edits by hand or asks for a revision. Approval writes the publish record.
Trade-off
Orchestration is never model-driven: cron, a queue and a state machine move each article, and the model only translates. That gives up agent flexibility for runs that can be replayed and audited. There is no retrieval step either: saved name renderings come from a plain database lookup.
Evidence
Each response is checked in code: it must parse, and every segment must come back, in order. One corrective retry, then the article stops. Refusals and truncated output are never retried. An offline evaluation harness scores names kept, glossary use, numbers, leftover English and length against thresholds. A daily spend cap is checked before every paid call.

04 / 04

Agentic Personal Assistance System

In daily use

A personal assistant on my own machine: it briefs, watches and delegates, with layered memory and written permission boundaries.

Problem
An assistant that runs on a schedule, spends money on model calls and starts engineering work is only useful if it cannot act beyond what it was granted, and if what it did can be checked afterwards.
Approach
An agent gateway on my own machine answers over Telegram. Scheduled jobs send briefs through the day and run news, market and job-scan radars. Engineering work is handed to Claude Code as tracked background jobs; cloud delegation returns its results as pull requests, which the agent never merges. Memory has layers: native notes behind a write gate, a learned model of the operator in Honcho, and an Obsidian vault for durable knowledge.
Trade-off
Permissions are deny-first: paid calls, publishing and sending need my approval, and deny rules block credential files and permission-bypass flags. Recalled memory may shape how it works, but can never authorise an action. Calendar and mail are not connected in the current version, and scheduled runs get no long-term memory.
Evidence
A weekly health check, built without a model call, reports the gateway, the scheduled jobs, the nightly encrypted backup, the last restore test, disk space and model cost. Cost is estimated per message, per day and per week. A local, read-only dashboard shows the current state. Secrets stay out of git.

Crypto Trading Core

A trading system that refuses bad trades.

  • Python
  • KuCoin spot

How it earns trust

  • Strategy validation: backtests run through the real engine and risk gate. Tests are registered in advance, the held-out data can be used once, and a purged walk-forward re-picks settings from earlier data only.
  • Risk controls: every order passes a gate that fails closed: stale data, a tripped breaker or any error rejects it. Per-trade risk, daily loss, drawdown and exposure have hard ceilings in code, with no leverage.
  • Execution boundaries: spot orders on one exchange. Live sending is switched off in code; arming it needs a dated arm file, a clear kill switch and a venue self-check. Breakers stay tripped until a named person resets them.
  • Evidence-based testing: fault injection and seeded property tests on the risk gate, replay tests that compare simulated decisions with the backtester, and an append-only, hash-chained journal.

Prediction-Market Systems

Prove the edge before capital moves.

  • Python
  • Polymarket CLOB
  • Binance data

How it earns trust

  • Strategy validation: a validator tests a market-making idea on free data and returns GO, KILL or INCONCLUSIVE. KILL is the default, every uncertain setting is chosen to make the edge look worse, and GO needs the confidence interval on net edge to stay above zero.
  • Risk controls: the latency-arbitrage engine sizes with fractional Kelly under a hard cap per trade, needs a minimum mispricing, limits trades per hour and stops on a session drawdown.
  • Execution boundaries: both systems run dry by default. Going live takes two separate explicit switches, and the market maker stays blocked until its fill channel has been checked against a real fill.
  • Evidence-based testing: a deterministic core with input and output injected, so replay tests rerun the whole pipeline. Prices come from the live order book, never from summary figures.
