01 / 05

CMA: Cost Monitoring Agent

Open source

LLM cost monitoring and attribution, with a RAG assistant that explains why the bill moved.

Read the case studyHide the case study
Problem
A provider's billing page shows a total. It does not say which agent spent it, on which model, or why spend changed.
Approach
A Python SDK patches OpenAI, Anthropic and LangChain clients in place and records tokens and cost at the call site. A FastAPI service attributes spend per agent, model and provider, checks budgets set globally or per agent and workflow, and alerts by webhook, Slack or in the app as a budget fills. Scrooge, the built-in RAG assistant, embeds cost events and rollups into a vector store and explains spend changes with cited sources. SQL stays the source of truth: Scrooge answers “how much” from SQL and uses retrieval only for “why”, and the vector store is a cache that can be rebuilt without losing data.
Evidence
The source is public under the MIT licence and runs on your own infrastructure with Docker Compose. A failure in the SDK never breaks the LLM call it wraps. CI checks that every database migration is reversible against a real PostgreSQL.

02 / 05

Aegis

Private repository

Crash-test agents before they ship: scenarios, injected faults and a release gate.

Read the case studyHide the case study
Problem
A release needs evidence of how an agent behaves when its tools fail, before it ships.
Approach
Runs the agent under test against versioned scenarios in an isolated sandbox with no network and no credentials, so the agent only ever sees simulated tool results and injected faults. Each candidate is compared with the baseline and passes a release gate with versioned policies; traces export to OpenTelemetry.
Evidence
A reference agent that is defective on purpose fails its scenario on every repetition, and the idempotent version passes. Approving a release needs a separate approver credential, and the API refuses an approval without it.
  • Python
  • REST API
  • OpenTelemetry

The console shown runs on demo data, and a live model is not supported yet.

FinPulse

Live demo

A portfolio tracker, and the serverless AWS platform and delivery pipelines that run it.

Read the case studyHide the case study
Problem
The dashboard is the visible part. Behind it, one engineer has to run sign-in, market data, an AI copilot and payments reliably, and ship changes safely.
Approach
Terraform defines the platform: Lambda functions behind API Gateway with a Cognito authoriser and throttling, DynamoDB on demand, secrets in Secrets Manager, and the React front end on S3 behind CloudFront. Separate GitHub Actions pipelines cover checks, security scans, infrastructure and deploys. An AI copilot answers questions about your positions from its own function.
Evidence
The site is public at finpulse.me. CloudWatch alarms watch Lambda errors and API errors and latency. DynamoDB has point-in-time recovery. Market data falls back from memory to a cache table, then the live API, then a static copy. Infrastructure changes apply only from a saved Terraform plan.

04 / 05

CISO Agent

Open source

A security officer inside every coding agent's loop.

Read the case studyHide the case study
Problem
Coding agents run shell commands, edit files and push code, and a language model can be manipulated by what it reads.
Approach
A hook on the engineer's machine checks each command, file edit and push before it runs, judging commands by their text. Fixed policy rules decide deny, ask or allow, with no model in the decision path. It ships as one Claude Code plugin, locked by organisation settings.
Evidence
Hooks fail closed: a crash, a timeout or a tampered ruleset blocks the action. In real runs with Claude Code, a force push to main and a file containing a fake cloud key were both denied. Switching a guard off makes a named test fail.
  • Python
  • Claude Code hooks
  • Policy as code
Source on GitHub (CISO Agent, opens in a new tab)

Built and tested, not yet deployed. It runs in the user's own space, so it stops the agent, not a determined person with admin rights on their own machine.

Autonomous Video Studio: Clay Town

Live demo

An autonomous studio that writes, animates and publishes a claymation series, with review gates before anything is paid for.

Read the case studyHide the case study
Problem
A short-form series needs a steady run of episodes with one consistent character. Every generated take costs money, so a weak story has to be rejected before anything is paid for.
Approach
Three engines share one record per episode. Claude drives story and orchestration: it drafts each episode, and story gates check the draft before any media is generated. The media engine builds one short clip per beat: a keyframe still with the character locked by a reusable element, animated with its own ambient sound and upscaled, then ffmpeg assembles the clips with the voiceover and burns in the captions. The publishing engine sends the finished episode to Instagram and YouTube from that same record.
Evidence
The series is public on Instagram and YouTube, and the episode above came out of this pipeline. One assembler script builds every series from a per-episode config. Views and retention are read back from YouTube Analytics and Instagram insights into an append-only history, because the platforms only return today's numbers.

Agentic Personal Assistance System

A personal assistant on my own machine: it briefs, watches and delegates, inside written permission boundaries.

  • Hermes Agent
  • Claude Code
  • Telegram
  • Honcho
  • Obsidian
  • Python
  • SQLite
  • Kopia
What it does

On the card: Chief, the assistant, as an architecture diagram of its interface, jobs, memory and integrations.

  • Problem: an assistant that runs on a schedule, spends money on model calls and starts engineering work is only useful if it cannot act beyond what it was granted, and if what it did can be checked afterwards.
  • Approach: an agent gateway on my own machine answers over Telegram; scheduled jobs send briefs and run news, market and job-scan radars. Engineering work goes to Claude Code as tracked background jobs, and cloud delegation comes back as pull requests the agent never merges. Memory has layers: native notes behind a write gate, a learned model of the operator in Honcho, and an Obsidian vault.
  • Boundaries: permissions are deny-first. Paid calls, publishing and sending need my approval, and recalled memory can never authorise an action. Calendar and mail are not connected in the current version.
  • Evidence: a weekly health check, built without a model call, reports the gateway, the scheduled jobs, the nightly encrypted backup, the last restore test, disk space and model cost. Runs locally; private repositories.

Crypto Trading Core

A trading system that refuses bad trades.

  • Python
  • KuCoin spot
How it earns trust
  • Strategy validation: backtests run through the real engine and risk gate. Tests are registered in advance, the held-out data can be used once, and a purged walk-forward re-picks settings from earlier data only.
  • Risk controls: every order passes a gate that fails closed: stale data, a tripped breaker or any error rejects it. Per-trade risk, daily loss, drawdown and exposure have hard ceilings in code, with no leverage.
  • Execution boundaries: spot orders on one exchange. Live sending is switched off in code; arming it needs a dated arm file, a clear kill switch and a venue self-check. Breakers stay tripped until a named person resets them.
  • Evidence-based testing: fault injection and seeded property tests on the risk gate, replay tests that compare simulated decisions with the backtester, and an append-only, hash-chained journal.

Prediction-Market Systems

Prove the edge before capital moves.

  • Python
  • Polymarket CLOB
  • Binance data
How it earns trust
  • Strategy validation: a validator tests a market-making idea on free data and returns GO, KILL or INCONCLUSIVE. KILL is the default, every uncertain setting is chosen to make the edge look worse, and GO needs the confidence interval on net edge to stay above zero.
  • Risk controls: the latency-arbitrage engine sizes with fractional Kelly under a hard cap per trade, needs a minimum mispricing, limits trades per hour and stops on a session drawdown.
  • Execution boundaries: both systems run dry by default. Going live takes two separate explicit switches, and the market maker stays blocked until its fill channel has been checked against a real fill.
  • Evidence-based testing: a deterministic core with input and output injected, so replay tests rerun the whole pipeline. Prices come from the live order book, never from summary figures.

Editorial Automation Platform

Scheduled news ingestion, structured LLM translation with quality checks, and an editor's approval before anything is published.

  • Cloudflare Workers
  • D1
  • Queues
  • Cron Triggers
  • Access
  • Claude API
  • TypeScript
What it does
  • Problem: a Hebrew magazine wants English-language news translated quickly. Names, terms and right-to-left layout have to survive, and nothing may go out unreviewed.
  • Approach: a cron trigger pulls allow-listed feeds, and each new article becomes one queue message with retries and a dead-letter queue. One model call must return JSON matching a schema, with fixed glossary terms masked before the call and restored after it. Cron, a queue and a state machine move each article; the model only translates.
  • Review: every article waits in a review queue behind Cloudflare Access, where an editor approves, rejects, edits by hand or asks for a revision. Approval writes the publish record.
  • Evidence: each response is checked in code: it must parse, and every segment must come back, in order. One corrective retry, then the article stops and waits for a person; refusals and truncated output are never retried. A daily spend cap is checked before every paid call.
  • Private repository. The engine runs unattended on its schedule ahead of launch; the magazine site is on staging.
